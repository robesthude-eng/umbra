# Задачи для GPT-6 Astra (ассистента)

Ты — ассистент-инженер в проекте **Umbra** (приватный мессенджер, аналог Telegram).
Серверная часть — на Go, лежит в `/home/user/server`. Клиент (Android) — на Kotlin.

Работай по задачам ниже, строго по одной. Каждую задачу выполняй до конца:
полный компилируемый код + краткое описание изменений + как проверить.
Не пропускай файлы, не пиши «…здесь остальной код». Придерживайся существующей
структуры и стиля (пакеты в `internal/`, домен в `internal/model`, хранилище в `internal/store`).

> 📌 Есть референс-проект «Vela» (Telegram-клон): разбор — в `docs/vela-analysis.md`.
> Из него берём **концепции** (фиче-лист, WebRTC-паттерн, схему данных, UX), код НЕ переносим.
> Криптография у нас строже: E2E всегда, Signal Protocol, forward secrecy.

---

## Задача 1 — Документация API (docs/api.md)
Опиши все эндпоинты с примерами запросов/ответов (curl + JSON), включая коды ошибок.
Отдельно распиши flow аутентификации (challenge → verify) и формат pre-key пакета.

## Задача 2 — Тесты сервера
Покрой юнит-тестами (стандартный `testing`):
- `internal/crypto` — все функции;
- `internal/store` (memory) — CRUD, конфликт username, одноразовость pre-key;
- `internal/httpapi` — регистрация, auth-flow, отправка/получение сообщения
  (используй `httptest` + fake hub). Сделай так, чтобы `go test ./...` проходил.

## Задача 3 — Медиа и файлы (Этап 2)  ← ВЫПОЛНЯЕТСЯ СЕЙЧАС (отдельный бриф task_for_astra.md)
Добавь эндпоинты загрузки/скачивания зашифрованных медиа:
- `POST /v1/media` (multipart, ciphertext + blob) → возвращает media_id;
- `GET /v1/media/{id}` → отдаёт blob;
- метаданные файла (имя, размер, mime) — минимальны и тоже хранятся без утечек.
Хранилище: абстракция в `internal/store` (memory + postgres), сами блобы — в отдельной
абстракции `internal/blobstore` (filesystem сейчас, S3/MinIO позже). Лимит размера из конфига.
> Референс из Vela: `message.media` — ссылка на зашифрованный blob, `kind` = photo/voice/file.

## Задача 4 — Групповые чаты и каналы (Этап 3)
Заимствуй модель данных из Vela (`chats`, `chat_members`, `contacts`, `typing`), но адаптируй:
- `chats` (id, type = dm/group/channel/saved, title, created_by) — без хранения открытого текста;
- `chat_members` (chat_id, user_id, role) — + групповые ключи (Sender Keys) хранятся на клиенте;
- `messages.body` — НЕ хранить: только `ciphertext BYTEA` (у нас уже так).
Эндпоинты:
- `POST /v1/groups`, `POST /v1/groups/{id}/members`, `POST /v1/groups/{id}/messages`;
- рассылка зашифрованного сообщения всем участникам через WS-хаб;
- сервер НЕ расшифровывает групповые сообщения (только пересылает ciphertext).
Дополнительно: контакты (`POST/GET /v1/contacts`), индикатор «печатает» (эфемерный, TTL).

## Задача 5 — Звонки (Этап 4)
Реализуй сигналинг для голосовых/видеозвонков, заимствуя WebRTC-паттерн из Vela:
- perfect negotiation (polite/impolite peer) — см. docs/vela-analysis.md §3.2;
- сигналинг через наш WS-хаб (НЕ поллинг БД): `offer`/`answer`/`ice` relay между peers;
- таблицы `calls` и эфемерный ростер peer'ов (TTL);
- медиа-канал end-to-end: ключи согласуются через libsignal, DTLS fingerprint сверяется
  вне канала; сервер — только ретранслятор сигналов.
Статусы звонков: ringing/active/ended/missed/declined.

## Задача 6 — Конфигурация деплоя
- `docs/deploy.md`: reverse-proxy (Caddy) с TLS, systemd-юнит, советы по выбору
  провайдера вне РФ, hardening (fail2ban, ufw, отключение root-входа по паролю);
- готовый `Caddyfile` и `umbra.service`.

## Задача 7 — Android-клиент (Этап 1, закладка)
Заложи структуру Android-клиента (Kotlin, Gradle, Compose, MVVM): модули, классы
для Signal Protocol (через libsignal), Room-БД для офлайн-очереди, Retrofit/OkHttp
клиент под этот API.
UX-референс из Vela: вкладки Chats/Contacts/Calls/Settings, пузыри сообщений,
reply-превью, unread-бейджи, замок на E2EE-чатах (см. docs/vela-analysis.md §3.4).
Полный функционал — отдельными задачами.

**Правила для каждой задачи:**
1. Сначала покажи, какие файлы создашь/изменишь.
2. Пиши код целиком, без сокращений.
3. Секреты — только через env, никогда в коде.
4. После кода — команды проверки (сборка/тесты) и что должно получиться.
5. Код из Vela не копировать; используй только как концептуальный референс.
