# Исправления пользовательских сценариев Umbra 0.4.1

Исходный материал: переданный архив `umbra-main.zip`.
Серверные маршруты, подпись приложения и существующие данные не менялись
на реальном сервере или устройстве. Ни CI, ни публикация APK не запускались.
Изменения подготовлены в исходниках; сборку и проверку на Android ещё нужно выполнить.

## Вход и профиль

- Формы прокручиваются и учитывают клавиатуру/системные панели.
- Оба шага входа используют одинаковую нормализацию телефона, включая неразрывные пробелы.
- Текст объясняет действующий способ доставки: код приходит владельцу Umbra в Telegram.
- Добавлен повторный запрос кода с интервалом 60 секунд, понятные ошибки неверного/истёкшего кода.
- Системная кнопка «Назад» возвращает с кода к номеру; профиль после авторизации не возвращается к уже использованному коду.
- Никнейм проверяется по правилам сервера: ASCII-буквы, цифры и `_`, 3–32 символа.
- Ошибка аватара больше не скрывается; можно выбрать другое фото или убрать выбранное.
- Изменение имени/никнейма сохраняет аватар, фамилию можно очистить пустым полем.
- Профиль возвращает фамилию через GET account; вход восстанавливает id аватара.
- Фото читаются с лимитом 10 МБ до накопления лишних данных; декодирование, уменьшение и EXIF-поворот выполняются вне UI-потока. Кэш байтов ограничен 20 МБ.

## Чаты, очередь и синхронизация

- Исправлено имя поля `client_message_id` в обоих запросах отправки. Ранее уходил `client_id`, который сервер игнорировал.
- Повтор отправки использует прежний id. REST, WS и ответ POST согласуются с локальной записью в транзакции.
- `GET /v1/messages` возвращает идентификатор подтверждения и в memory-, и в PostgreSQL-хранилище.
- Исправлен курсор пагинации: дробная часть секунды не обрезается. Добавлена защита от зацикливания на неизменной странице.
- Неотправленные локальные сообщения не сдвигают курсор серверной истории. Работает периодическая полная сверка.
- Пустые личные диалоги видны в списке; группы восстанавливаются с сервера, включая группы без сообщений.
- Текст ввода очищается после сохранения в очередь. Состояния «ожидает отправки», «отправлено», «не отправлено» различаются; у ошибки есть повтор.
- Сохранены черновик, положение списка и вкладка при обычной навигации/пересоздании Activity. Есть копирование текста и переход к последним сообщениям.
- Повторный вход в тот же аккаунт сохраняет очередь; смена аккаунта очищает локальную базу.
- Локальные записи защищены от ответа устаревшей сессии, WS-события привязаны к токену соединения. Убраны лишние подписки на состояние соединения.
- Истёкшие сообщения удаляются локально и без сети.
- Проблема соединения видна на основных экранах; предусмотрено ручное обновление.
- Неизвестные/старые конверты не показывают пользователю сырой base64.

## Группы, вызовы и настройки

- Ошибки поиска, создания группы и приглашения участников не маскируются как успех.
- Повтор приглашения после частичного сбоя работает с уже созданной группой; можно открыть её и добавить участников позднее.
- Добавлен список участников; сервер проверяет права приглашения, ошибки отображаются.
- При прекращении доступа к группе сохранённая история остаётся читаемой, ввод блокируется.
- Исправлен DTO статуса вызова: сервер возвращает только `status`.
- Кнопки вызова освобождаются в `finally`, завершение доступно после ответа. Ошибки видны; при сетевой проблеме окно можно закрыть локально.
- Исправлены имя во входящем вызове и русские названия статусов. Тестовый вызов без ответа пытается завершиться через минуту.
- Отсутствие аудио/видео обозначено до отправки вызова и в его окне; статус «На связи» больше не выдаётся за рабочую голосовую связь.
- Удаление аккаунта не объявляется успешным при отказе сервера. Локальные данные очищаются после подтверждённого ответа.
- Диалоги блокируют повторное нажатие во время запроса, показывают ошибки и дают повторить действие.
- Цвета элементов согласованы со светлой/тёмной темой; исправлен контраст текста на формах и в сообщениях.
- Docker Compose передаёт четыре параметра Telegram, добавлены примеры настройки в `.env.example`.
- Документация приведена к текущей облачной модели без Signal. Android versionCode: 6, versionName: 0.4.1; Room остаётся версии 3.

## Фактически выполненные проверки

- Разобраны 8 XML, 2 JSON-схемы, каталог TOML и 3 YAML-файла.
- Проверено закрытие строк/комментариев и скобок в 85 исходниках Go/Kotlin/Gradle. **Это не проверка компилятором.**
- Все 12 SQL-команд миграций Room 1→2→3 выполнены на SQLite. Старая строка с ciphertext сохранена, наборы столбцов совпадают со схемой версии 3.
- Запросы DAO выполнены на SQLite: курсор исключает pending; очередь и подтверждения разделены по владельцу; истечение срабатывает на границе срока и не удаляет pending без срока.
- Все 24 Retrofit-маршрута сопоставлены с хендлерами переданного Go-сервера.
- Проверены целостность итогового ZIP и совпадение каждого упакованного файла с рабочими исходниками.

Java 17 удалось запустить с настройкой пути к его библиотекам. В окружении отсутствуют
Go, Android SDK, Gradle с зависимостями и Android-устройство. Поэтому **go build/vet/test,
Gradle compile/lint, PostgreSQL/S3 integration и instrumented-тесты не выполнялись**.
Успешная компиляция и работа на телефоне этим архивом не подтверждены.

## Добавленные регрессии для запуска в окружении проекта

`android/app/src/androidTest/java/com/umbra/app/data/UserFlowsTest.kt`:
потерянное подтверждение, повтор failed-сообщения, повторный вход и смена аккаунта,
отказ удаления, сохранение аватара/очистка фамилии, пустой DM, различение 404 и
сетевой ошибки, ответ статуса вызова, восстановление групп/точный курсор,
согласование REST с очередью.

Go: расширены тесты профиля/повторного входа и сохранения `client_message_id`;
контракт хранилища проверяет подтверждение и на memory, и на PostgreSQL.
Существующий тест миграции Room сохранён.

Команды:

```bash
go build ./...
go vet ./...
go test -race -count=1 ./...
cd android
./gradlew assembleDebug assembleDebugAndroidTest lintDebug
./gradlew connectedDebugAndroidTest
```

Для PostgreSQL задайте отдельный `TEST_DATABASE_URL`; для Android подключите
эмулятор/телефон. Не используйте рабочую БД для интеграционных проверок.

## Что нужно проверить на телефоне перед выпуском

1. Вход с неверным/истёкшим кодом, повтор кода, поворот экрана и открытая клавиатура.
2. Профиль с длинным именем, занятым/неверным никнеймом, смена фото и удаление фамилии.
3. Переписка двумя аккаунтами: offline→online, повтор ошибки, длинная история, выход/повторный вход.
4. Создание группы, отказ при приглашении, повтор без создания второй группы, просмотр участников.
5. Приём/завершение тестового вызова и потеря сети во время вызова.
6. Ошибка удаления аккаунта, светлая/тёмная тема, крупный системный шрифт, системная кнопка «Назад».

Это исправление существующих сценариев, а не реализация отсутствующих подсистем:
аудио/видео, push при остановленном приложении, полноценные файловые вложения
и сквозное шифрование остаются отдельными задачами. Черновики UI не гарантируются
после принудительной остановки/очистки данных. Прерванный запрос создания группы
может иметь неопределённый результат, если сервер обработал его, а ответ не дошёл;
перед повторным созданием нужно обновить список групп.
