# Umbra — план развития и статус функций

Этот файл — единый источник правды по продуктовым доработкам. Его необходимо обновлять в том же изменении, в котором реализуется функция.

## Как вести статусы

- [x] **Готово** — код реализован, статические проверки пройдены, указана версия.
- [~] **Частично** — работает только часть сценариев; ограничения перечислены рядом.
- [ ] **Запланировано** — реализация ещё не начата.
- [!] **Заблокировано** — есть внешняя зависимость или архитектурное препятствие.

Функцию разрешено отмечать как готовую только после выполнения её критериев приёмки. При каждом обновлении нужно:

1. изменить статус пункта;
2. указать фактическую версию и дату;
3. добавить запись в `CHANGES.md`;
4. перечислить известные ограничения;
5. обновить автоматическую проверку в `scripts/audit-client-features.py`, если функцию можно проверить статически;
6. после доступной Android-сборки записать результат компиляции, Lint и device QA.

**Критерии приёмки 0.17.0**

- Задача создаётся из личного и группового чата.
- Ссылка открывает исходное сообщение или понятное состояние, если оно удалено.
- Повторная отправка не создаёт дубликат задачи.
- Изменения статуса синхронизируются минимум между двумя устройствами.
- Сроки корректно работают после смены часового пояса.
- Выполнены миграции сервера и Room с тестом обновления существующей базы.
