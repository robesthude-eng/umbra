# Umbra Android 0.9.0

Клиент на Kotlin 2.0.20, Compose, Room 2.6.1 и Retrofit. Минимальная версия
Android — 8 (API 26), целевая — API 35. В этой ветке используется облачная
модель T1: сообщения — JSON в base64, сквозного шифрования нет.

## Сборка

Нужны JDK 17 и Android SDK 35; wrapper использует Gradle 8.9.

```bash
./gradlew assembleDebug
./gradlew assembleDebug -Pumbra.serverUrl=https://your-server.example
./gradlew assembleRelease -Pumbra.serverUrl=https://your-server.example
```

Также поддерживается переменная `UMBRA_SERVER_URL`. URL должен указывать
на корень сервера, без пути, query и встроенных учётных данных. Debug без
настройки использует `http://10.0.2.2:8080/`. Для телефона через USB можно
использовать `adb reverse tcp:8080 tcp:8080` и URL `http://127.0.0.1:8080/`.
Существующий тестовый HTTP-адрес сохранён в debug network security config.
Для другого сетевого адреса используйте HTTPS; release допускает только HTTPS.

Текущая версия в исходниках — **versionCode 13, versionName 0.9.0**
(`android/app/build.gradle.kts`). Номер предыдущей версии по архиву не
восстанавливается: здесь ранее был указан versionCode 7, а в `USER_FIXES.md` — 6;
сверьте с историей репозитория. Для установки поверх прежней версии
необходим тот же ключ подписи. Схема подписи `UMBRA_SIGNING_*` и
`keystore.properties` сохранена. Без стабильного ключа debug использует ключ
локального Gradle, а release нужно подписать отдельно. Не удаляйте приложение
ради обхода несовпадения подписи: это уничтожит его локальные данные.

## Поведение аккаунта

Полная синхронизация продлевает действующую сессию через `POST /v1/auth/refresh`.
По умолчанию сервер даёт 30 дней после продления. Токен не заменяется, поэтому
потерянный ответ не приводит к потере входа. Старый сервер (404/405 на этом маршруте)
продолжает обслуживать клиент с прежним сроком токена; для продления обновите сервер.
Миграция сервера 011 требует один повторный вход и сохраняет переписку.

Код из шести цифр приходит владельцу Umbra в Telegram; он передаёт его
регистрирующемуся пользователю. Повторный запрос доступен через минуту.
Никнейм: 3–32 латинские буквы, цифры или `_`, префикс `@` при вводе необязателен.
Имя обязательно, фамилию можно удалить, сохранив пустое поле.

Выход удаляет локальный токен сразу и отдельно пытается отозвать его на сервере.
При отсутствии связи удалённый токен остаётся действительным до своего TTL.
История и очередь отправки остаются на устройстве для повторного входа в тот же
аккаунт. При входе в другой аккаунт локальная база очищается до смены владельца.
Ответы старой сессии не должны записываться в данные новой.

Удаление аккаунта очищает локальную базу только после успешного ответа сервера.
Ошибка оставляет диалог с возможностью повторить действие. При обрыве связи
после обработки запроса сервером результат может оставаться неопределённым;
интерфейс не сообщает об успешном удалении без подтверждения.

Профиль и токен хранятся в EncryptedSharedPreferences. История сообщений и кэш
карточек в Room не зашифрованы. Старые криптографические таблицы сохранены для
совместимости схемы; это не делает текущую переписку зашифрованной.

## Переписка и группы

Текст сначала сохраняется локально, затем отправляется с `client_message_id`.
Повтор использует тот же идентификатор. REST/WS-подтверждение заменяет локальную
запись без дубля. Сетевые ошибки оставляют сообщение в очереди, постоянные ошибки
показывают кнопку повторной отправки. Максимальная длина текста — 16 000 символов.

Группы загружаются с сервера, включая пустые. Если доступ прекращён, сохранённую
историю можно читать, а отправка блокируется. При частичной ошибке приглашения
можно повторить добавление в уже созданную группу; серверный конфликт «уже
участник» считается успешным результатом.

В чате работают системная кнопка «Назад», кнопка перехода к последним сообщениям,
копирование текста и сохранение черновика при обычной навигации/повороте экрана.
Черновики хранятся в состоянии интерфейса, не являются отдельной облачной функцией
и не гарантируются после принудительной остановки приложения.

Фото профиля читается с лимитом 10 МБ, декодируется вне главного потока с
уменьшением размера и учётом EXIF-ориентации. Кэш байтов ограничен 20 МБ.

## Голосовые сообщения

Запись — `MediaRecorder` из Android SDK: AAC в контейнере MP4 (`audio/mp4`, `.m4a`),
44,1 кГц, 64 кбит/с. Новых зависимостей не добавлено. Кнопка микрофона стоит
в пустом поле ввода и сменяется на «Отправить», как только набран текст. Во время
записи видны таймер, индикатор громкости и кнопка отмены. Предел — 5 минут:
запись останавливается сама и ждёт отправки или отмены. Записи короче 0,7 секунды
не отправляются. Уход с экрана чата отменяет недозаписанную запись и глушит звук.

Разрешение `RECORD_AUDIO` (уже было в манифесте) запрашивается при первом
нажатии на микрофон. Отказ показывает подсказку и не ломает остальной чат.

Отправка идёт той же очередью, что и текст: строка появляется сразу со статусом
«Ожидает отправки», а файл переносится в приватный каталог `files/voice/outbox`.
В очереди запись сначала загружается в `POST /v1/media`, затем уходит конверт
`kind: "voice"` с `media.id`, `media.mime` и `media.durationMs`. Признак уже
загруженной записи — непустой `ciphertext` в локальной строке, поэтому обрыв
связи между загрузкой и отправкой не создаёт вторую копию на сервере. Сетевые
ошибки, 5xx, 408 и 429 повторяются с сохранением порядка; 413 и 507 показывают
отдельные тексты о размере и месте на сервере. Лимит одного файла — 24 МБ.

Проигрывание — `MediaPlayer`: активна одна запись, прогресс обновляется каждые
200 мс. Свои записи играются из локального файла, входящие скачиваются в
`files/media` по `media.id` и кэшируются; кэш ограничен 256 МБ и чистится с самых
старых файлов. Смена аккаунта и удаление аккаунта удаляют локальные файлы
записей вместе с базой.

Полоса прогресса в пузыре голосового — ползунок: перетаскивание вызывает
`VoicePlayer.seekTo`. Рядом кнопка скорости 1× / 1,5× / 2× (`setSpeed`).
Скорость запоминается и применяется при следующем запуске: `setPlaybackParams`
на части прошивок сам снимает паузу.

## Звонки

Звонок бывает личным и групповым. В групповом чате кнопки вызова
открывают диалог выбора участников — до трёх, то есть четверо в разговоре
вместе с вами. Медиа идёт mesh-схемой: `CallEngine` держит отдельное
соединение с каждым собеседником, а экран звонка показывает сетку плиток:
видео там, где камера включена, иначе аватарка и состояние связи.
Выход одного участника не завершает разговор остальным: сервер присылает
`call_status` с полем `from`, и клиент убирает только его плитку.

Медиа идёт напрямую между устройствами (WebRTC, `io.github.webrtc-sdk:android`).
Через сервер проходят только сигналы: `POST /v1/calls` создаёт вызов,
`POST /v1/calls/{id}/signal` переносит offer, answer и ICE-кандидатов,
`POST /v1/calls/{id}/status` меняет статус. Роли фиксированы: инициатор
отправляет offer и повторяет его до трёх раз, если ответ не пришёл.

Движок звонка (`data/call/CallEngine.kt`) живёт в `AppContainer`, то есть
принадлежит приложению, а не экрану: поворот телефона и сворачивание не рвут
разговор. Пока звонок активен, работает служба переднего плана
(`data/call/CallService.kt`, типы `microphone|camera`) — с Android 14 без неё
система глушит захват звука в фоне.

Разрешения запрашиваются на экране звонка: `RECORD_AUDIO` всегда, `CAMERA` для
видео, `POST_NOTIFICATIONS` на Android 13+ (без него не видно уведомление
звонка, сам разговор работает). Отказ в микрофоне завершает звонок понятным
текстом, а не тишиной.

С 0.7.0 адреса ICE клиент запрашивает у сервера (`GET /v1/turn`) перед каждым
звонком: учётка TURN там временная и в APK не сохраняется. Значения из сборки
остались запасным вариантом на случай, если сервер недоступен:

```bash
./gradlew assembleRelease -Pumbra.serverUrl=https://your-server.example \
  -Pumbra.stunUrl=stun:stun.l.google.com:19302 \
  -Pumbra.turnUrl=turn:turn.your-server.example:3478 \
  -Pumbra.turnUser=umbra -Pumbra.turnPassword=ЗАМЕНИТЕ_ПАРОЛЬ
```

Те же значения читаются из `UMBRA_STUN_URL`, `UMBRA_TURN_URL`,
`UMBRA_TURN_USER`, `UMBRA_TURN_PASSWORD`. По умолчанию STUN — публичный сервер
Google, TURN не задан. Список с сервера важнее: зашитые адреса идут в дело,
только когда запрос `GET /v1/turn` не прошёл.

Нативный WebRTC добавляет к APK примерно 25 МБ на архитектуру. ABI-фильтры не
включены, поэтому один APK содержит все архитектуры; при необходимости включите
splits или App Bundle. В ProGuard добавлено `-keep class org.webrtc.** { *; }`.

## Push-уведомления

Токен Firebase Cloud Messaging приложение регистрирует при каждом запуске
(`data/push/PushService.kt`, `ChatRepository.registerPushToken`) и отвязывает
при выходе из аккаунта. Сервер присылает только data-сообщения, поэтому текст
переписки через Google не проходит, а уведомление всегда рисует приложение.

- `kind=message` — уведомление о новом сообщении с именем отправителя, канал
  `umbra_messages`; при открытии история догружается.
- `kind=call` — полноэкранное уведомление входящего вызова поверх блокировки:
  канал `umbra_incoming_calls`, рингтон, кнопки «Ответить» и «Отклонить»
  (`data/call/CallNotifications.kt`). «Отклонить» отправляет статус `declined`
  без открытия приложения, само уведомление снимается через 45 секунд.
- `kind=call_ended` — уведомление гаснет, когда звонящий бросил трубку.

Сборка без `google-services.json` проходит и работает: плагин
`com.google.gms.google-services` применяется только при наличии файла, а код
проверяет, инициализирован ли Firebase. В этом случае уведомления приходят
только при запущенном процессе, как в 0.7.0.

На Android 13+ нужно разрешение на уведомления, для экрана поверх блокировки —
`USE_FULL_SCREEN_INTENT`. Активность открывается с `setShowWhenLocked` и
`setTurnScreenOn`, поэтому вызов видно на заблокированном телефоне.

## Ограничения

- Групповой звонок ограничен четырьмя участниками: каждый шлёт свой поток
  каждому, и пятого мобильный канал уже не выдержит. Конференций на
  большее число людей нет — для них нужен медиасервер (SFU).
  При полностью закрытом приложении вызов доходит push-уведомлением,
  но только если владелец настроил Firebase.
- Без TURN звонок может не соединиться, когда оба участника за «серым» NAT
  мобильного оператора. Сам ретранслятор нужно поднять отдельно (профиль
  `turn` в `docker-compose.yml`), но учётка теперь временная и выдаётся сервером.
- Смена сети во время разговора обрабатывается перезапуском ICE: экран
  показывает «Восстанавливаю связь…», даётся 30 секунд и до пяти попыток.
  В каждой паре новый offer шлёт одна сторона: звонящий — приглашённым,
  а между приглашёнными тот, чей идентификатор меньше.
- Вложения в переписке: фото, видео и файлы отправляются, открываются и
  сохраняются на устройство, но без сжатия, подписей и пересылки;
  предел одного вложения — 48 МБ.
- Уведомление о сообщении не показывает текст: через Firebase уходят только
  идентификаторы и имя отправителя, сам текст приложение забирает с сервера.
- Клиенты 0.4.2 и старше не понимают `kind: "voice"`, а версии до 0.8.0
  включительно — `image`, `video` и `file`: вместо вложения появится «Этот
  тип сообщения пока не поддерживается». В групповой звонок версии до
  0.9.0 тоже не вступят: вызов покажут, но сигналы без адресата сервер
  отклонит. Обновите все устройства семьи.
- Запись идёт только при открытом экране чата: фоновой записи нет.
- Старые Signal-конверты не расшифровываются этим клиентом. Вместо base64 показывается
  сообщение о несовместимой версии.
- Смена внешних данных с другого устройства становится видна при полной
  синхронизации, в том числе по кнопке обновления; автоматическая полная сверка —
  каждые 15 минут и при переподключении.

## Проверка

```bash
./gradlew assembleDebug assembleDebugAndroidTest lintDebug
./gradlew connectedDebugAndroidTest
```

`DatabaseMigrationTest` проверяет сохранение старой истории при миграции Room.
`UserFlowsTest` проверяет очередь после потерянного подтверждения, повтор отправки,
повторный вход/смену аккаунта, отказ удаления, профиль/аватар, пустой диалог,
ошибки поиска, ответы статусов вызова, группы, точный курсор истории и отправку
голосового сообщения (загрузка в `/v1/media`, затем конверт `voice`, статусы пузыря).
Room обновлён до версии 4: `MIGRATION_3_4` добавляет в `messages` колонки
`localMediaPath`, `localMediaMime` и `localMediaDurationMs`. Файл схемы
`app/schemas/com.umbra.app.data.db.AppDatabase/4.json` генерирует KSP при сборке,
вручную его добавлять не нужно.

Сборка и instrumented-тесты в среде подготовки архива не выполнялись: Android SDK,
Gradle с зависимостями и устройство отсутствуют. Результаты доступных проверок:
[USER_FIXES.md](../USER_FIXES.md).
