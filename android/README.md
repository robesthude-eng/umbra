# Umbra — Android

Kotlin, Compose, Room и libsignal 0.60.1. Клиент поддерживает личную переписку
с E2E-медиа: фото/видео и произвольные файлы шифруются AES-256-GCM и едут как
opaque ciphertext (метаданные — только внутри Signal-конверта). Серверные API
групп и звонков существуют, но эти функции на Android ещё не завершены.
Отправка в группы отключена до реализации группового E2E.

## Сборка и адрес сервера

Нужны полный JDK 17, Android SDK 35 и доступ к репозиториям зависимостей.

```bash
cd android
./gradlew assembleDebug
./gradlew assembleDebug -Pumbra.serverUrl=https://messenger.example.org
./gradlew assembleRelease -Pumbra.serverUrl=https://messenger.example.org
```

Вместо Gradle-параметра можно задать `UMBRA_SERVER_URL`. Разрешён URL корня сервера,
без пути, query-параметров и встроенных учётных данных.

Debug по умолчанию использует `http://10.0.2.2:8080/`. Незашифрованный HTTP разрешён
только для `10.0.2.2`, `localhost` и `127.0.0.1`, только в debug. Для телефона
можно выполнить `adb reverse tcp:8080 tcp:8080` и собрать debug с
`-Pumbra.serverUrl=http://127.0.0.1:8080`. Для другого адреса нужен HTTPS.

Release требует заданный HTTPS URL, не содержит разрешения HTTP и не подписывается
debug-ключом. Подпишите APK своим существующим ключом через Android Studio или
свой процесс выпуска. Для обновления установленного приложения требуется тот же
ключ подписи: не удаляйте приложение ради установки обновления, иначе потеряете его данные.

## Аккаунт и ключи

Одна установка хранит один профиль. Регистрация сохраняет identity до первого
HTTP-запроса и использует тот же набор при повторе. Вход по имени возможен только
при наличии приватных ключей этого аккаунта на устройстве.

Выход удаляет локальный токен, закрывает соединение и пытается отозвать токен на
сервере. Ключи, профиль и зашифрованная история сохраняются. Если сети нет, локальный
выход происходит сразу, а неотозванный серверный токен остаётся действительным до
истечения TTL.

Ed25519 для аутентификации реализован через lightweight API Bouncy Castle, включая
Android 8 (API 26). Читаются прежние PKCS#8 private keys, сервер принимает прежние
X.509 public keys и новый raw-формат. Identity X25519 при обновлении сохраняется.

Для Signal подписанный pre-key подписывается identity-ключом Signal. Приватные
одноразовые ключи, идентичности собеседников, сессии и ratchet хранятся в Room под
AES-GCM, ключ AES находится в Android Keystore. Данные записи связаны с её адресом
через AAD. Старые private pre-keys сохраняются для сообщений в пути; автоматической
политики их удаления пока нет.

Публикация pre-key пакета имеет постоянный `key_bundle_id`: повтор после потери
ответа не возвращает уже выданные одноразовые ключи в серверную очередь. При входе,
восстановлении сохранённой сессии и затем раз в пять минут клиент проверяет запас
ключей на сервере и пополняет его при остатке менее 20.

## История и доставка

Encrypt/decrypt, изменение состояния Signal и запись сообщения выполняются в одной
Room-транзакции. При откате возвращается и состояние ratchet. Для показа истории
используется отдельная локальная AEAD-копия текста; повторного Signal-decrypt при
перерисовке экрана нет.

Исходящее сообщение сначала попадает в постоянную очередь. Поле ввода очищается
после успешной локальной записи. Повтор отправки использует прежний ciphertext и
`client_message_id`. Статусы «Ожидает отправки», «Отправлено» и «Не отправлено»
отражают локальную очередь и подтверждение сервера; это не подтверждение прочтения.

Клиент переподключает WebSocket с задержкой до 30 секунд и сверяет сообщения через
REST каждые пять секунд, пока процесс работает. При подключении и каждые 15 минут
выполняется полная сверка; обычная сверка использует курсор по времени сервера с
перекрытием 30 секунд. Страницы сортируются по времени и id. Полученный DM относится
к диалогу отправителя. Дубликаты с уже сохранённым текстом повторно не расшифровываются.

Сервер хранит квитанции повторной отправки 30 дней. Клиент прекращает повтор через
29 дней и предлагает уточнить доставку у собеседника. Просроченные сообщения
удаляются локально во время работы процесса, а после запуска — при первом проходе
очистки. Просроченные записи очереди больше не отправляются.

## Обновление с прежней версии

Сначала обновите сервер и примените миграцию 006 по инструкции в корне проекта.
Затем обновите оба Android-клиента с сохранением данных приложения.

Room мигрирует с версии 1 на 2 без удаления таблиц. Старые ciphertext, чаты и
записи identity сохраняются. После проверки аккаунта нормализуются владелец,
направление DM и временные метки. Публикация ключей v2 не заменяет identity.

Прежний клиент не сохранял ratchet, приватные одноразовые ключи и постоянную копию
отправленного текста. Если эти данные уже потеряны, обновление не восстановит
старый текст. Такие записи остаются в базе и отображаются с пояснением. Переустановка,
перенос на другое устройство и восстановление аккаунта по одному username не поддерживаются.

## Проверки

```bash
./gradlew assembleDebug assembleDebugAndroidTest lintDebug
./gradlew connectedDebugAndroidTest
```

Instrumented-тестам нужен эмулятор или устройство; реальный сервер не требуется.
Они используют отдельные тестовые профили и базы:

- две libsignal-сессии, ответ после перезапуска и следующий шаг ratchet;
- откат между decrypt и записью истории, включая восстановление pre-key;
- сохранение identity и pending-пакета при повторе регистрации;
- запрет подмены уже известной identity;
- миграция прежней SQLite-схемы с проверкой Room и удаление истёкшей записи;
- потеря HTTP-подтверждения, перезапуск outbox, неизменность ciphertext/id,
  правильный входящий диалог и ответ вторым клиентом через MockWebServer.

Workflow в корне запускает Android-проверки на API 26 и 35. Наличие тестов в архиве
не означает, что они были выполнены: фактический статус проверки указан в CHANGES.md.

## Оставшиеся ограничения

Нет группового E2E, файлового обмена, WebRTC, push-уведомлений при остановленном
процессе, UI настройки таймера, переноса ключей и экрана сверки fingerprints.
Первая identity собеседника принимается по TOFU; последующая замена блокируется.
Удаление строки из SQLite не является гарантией стирания всех её следов из WAL,
снимков накопителя или копий у собеседника.
