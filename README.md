# Umbra

Семейный мессенджер: Android на Kotlin/Compose и сервер на Go.
Эта версия клиента — **0.8.0 (versionCode 12)**: телефон будят push-уведомления
Firebase, поэтому сообщение и звонок доходят при полностью закрытом приложении,
а входящий вызов поднимается поверх блокировки с кнопками «Ответить» и
«Отклонить». В 0.7.0 сервер начал выдавать временные учётки TURN
(`GET /v1/turn`), а разговор перестал рваться при смене сети; в 0.6.0 появились
сами звонки на WebRTC, в 0.5.0 — голосовые сообщения. Сервер нужно обновить:
маршруты `POST`/`DELETE /v1/push/devices`, миграция `012_push_devices.sql`
и переменные `FCM_*` появились только в 0.8.0.

Документация: контракт HTTP API — [docs/api.md](docs/api.md) (сверен с исходниками
сервера 9 сентября 2026); развёртывание и обновление — [docs/deploy.md](docs/deploy.md);
поведение клиента — [android/README.md](android/README.md); история предыдущих
исправлений — [USER_FIXES.md](USER_FIXES.md).

## Возможности текущего Android-клиента

- Вход по номеру и шестизначному коду. Код получает **владелец Umbra в Telegram**
  и передаёт его пользователю. Это не SMS и не отправка в личный Telegram каждого пользователя.
- Профиль: имя, необязательная фамилия, никнейм и аватар.
- Личные текстовые сообщения, группы, просмотр и добавление участников.
- **Голосовые сообщения** в личных чатах и группах: запись с микрофона
  (AAC в контейнере `.m4a`), таймер и индикатор громкости, отмена до отправки,
  предел 5 минут, отправка через ту же очередь с повторами и прослушивание
  с прогрессом, перемоткой по полосе, скоростью 1× / 1,5× / 2× и кэшем
  на устройстве.
- Постоянная очередь отправки, повтор после ошибки, восстановление истории
  через REST и обновления через WebSocket.
- Светлая и тёмная темы, сохранение вкладки/черновика при переходах между экранами,
  прокрутка форм с клавиатурой, копирование текста сообщений.
- **Звонки** один на один: аудио и видео через WebRTC. Звук и видео идут
  напрямую между устройствами, через сервер проходят только сигналы.
  Полноэкранный входящий вызов с рингтоном, приём и отклонение, микрофон,
  громкая связь, включение и переключение камеры, таймер разговора и журнал
  вызовов. Разговор не рвётся при повороте экрана и сворачивании приложения.
- **Push-уведомления**: сервер будит телефон через Firebase, когда приложение
  закрыто. Новое сообщение приходит уведомлением (текста в нём нет — сервер его
  не передаёт), входящий звонок — полноэкранным уведомлением поверх блокировки
  с рингтоном и кнопками «Ответить» и «Отклонить»; когда звонящий бросает
  трубку, уведомление гаснет само. Нужны проект Firebase и ключ на сервере.

Модель хранения — облачная T1. `ciphertext` — историческое имя поля API:
Android кладёт туда base64 от JSON, это **не шифрование**. Текущий клиент не
использует Signal и не даёт сквозного шифрования. История в Room также не
зашифрована. Токен и профиль в настройках приложения защищены
EncryptedSharedPreferences. Для сети используйте HTTPS.

Отправка и просмотр файлов, фото и видео в чатах пока не реализованы:
поддержка медиа на сервере сама по себе не означает наличие этих возможностей
в интерфейсе. Загружаются аватары и голосовые сообщения — вложения в переписке
следующая запланированная работа.
Звонки работают только один на один: групповая конференция потребовала бы
отдельного медиасервера. Если оба собеседника за «серым» NAT мобильного
оператора, нужен TURN-сервер: coturn есть в `docker-compose.yml` профилем
`turn`, но поднимать его нужно отдельно — см. [docs/deploy.md](docs/deploy.md).
Смена сети во время разговора переживается: клиент перезапускает ICE и
показывает «Восстанавливаю связь…».

Важно при обновлении: клиенты 0.4.2 и старше не знают тип сообщения `voice`
и покажут вместо записи текст «Этот тип сообщения пока не поддерживается».
Звонок со звуком возможен только между устройствами с 0.6.0: клиент 0.5.0
покажет вызов, но останется без звука и видео.
Обновите приложение на всех устройствах семьи.

Push-уведомления не включаются сами: нужен проект Firebase, файл
`google-services.json` в `android/app/` при сборке APK и сервисный ключ на
сервере (`FCM_CREDENTIALS_FILE`). Без этого приложение собирается и работает
как в 0.7.0: уведомления приходят только при запущенном процессе. Порядок
настройки — в [docs/deploy.md](docs/deploy.md).

Старые документы в `docs/dev-notes` и прежние записи `CHANGES.md` отражают
историю разработки, включая прежнюю модель Signal. Они не описывают возможности
текущего клиента.

## Запуск сервера

Версия Go указана в `go.mod` (1.27); для постоянного хранения нужен PostgreSQL 16.

```bash
cp .env.example .env
# Заполните POSTGRES_PASSWORD, TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID.
docker compose up -d --build
```

Параметры Telegram теперь передаются в контейнер. Без токена бота и chat ID
владельца вход по коду недоступен. Необязательные `TELEGRAM_API_BASE` и
`TELEGRAM_API_KEY` нужны только при использовании существующего релея.

На новом томе PostgreSQL применяет миграции `001`–`011`. На существующей БД
сначала сделайте резервную копию, остановите сервер и примените только
отсутствующие миграции по порядку. Новая `011_revoke_legacy_sessions.sql` однократно
отзывает старые токены и коды переноса: пользователям нужно войти заново по OTP.
Аккаунты и переписка сохраняются. Не применяйте `011` повторно после нового входа.
Не запускайте старые миграции повторно вслепую. Общие инструкции:
[docs/deploy.md](docs/deploy.md); актуальный список миграций — каталог `migrations`.

Для разработки можно запустить сервер без PostgreSQL:

```bash
STORE=memory go run ./cmd/server
```

Переменные Telegram при таком запуске задаются в окружении; `go run` не читает
`.env` автоматически. Memory-хранилище теряет аккаунты и историю при перезапуске.
Не используйте его для постоянной семейной переписки.

Сессия по умолчанию действует 30 дней после входа/продления. Android продлевает
её при полной синхронизации (при запуске, переподключении и примерно раз в 15 минут).
Отозванный или истёкший токен продлить нельзя. Обновите прежний `TOKEN_TTL_SECONDS`
в `.env`, если там осталось `86400`. Вход по ключу отключён по умолчанию;
телефонные аккаунты всегда требуют код, даже при `ALLOW_LEGACY_AUTH=true`.

## Android

Нужны JDK 17, Android SDK 35, Gradle 8.9 через wrapper и доступ к репозиториям зависимостей.

```bash
cd android
./gradlew assembleDebug -Pumbra.serverUrl=https://your-server.example
```

Для эмулятора debug по умолчанию использует `http://10.0.2.2:8080/`.
Сохранена конфигурация существующего тестового HTTP-стенда из исходного проекта;
список разрешённых debug-адресов находится в
`android/app/src/debug/res/xml/network_security_config.xml`.
Release требует явно заданного HTTPS URL.

Для обновления установленного приложения используйте прежний ключ подписи.
Параметры стабильного ключа по-прежнему берутся из `keystore.properties` или
переменных `UMBRA_SIGNING_*`. Ключи не включены в архив. Подробнее:
[android/README.md](android/README.md).

## Проверки

```bash
go build ./...
go vet ./...
go test -race -count=1 ./...
```

Для проверки PostgreSQL задайте `TEST_DATABASE_URL` отдельной тестовой БД.
Существующие S3-тесты включаются через `TEST_S3_*`.

```bash
cd android
./gradlew assembleDebug assembleDebugAndroidTest lintDebug
./gradlew connectedDebugAndroidTest
```

Последняя команда требует устройства или эмулятора. `UserFlowsTest` проверяет
реальный Retrofit, Room и SessionStore с MockWebServer, отдельной базой и
отдельными настройками; данные установленного аккаунта не используются.

Для 0.4.2 добавлены регрессии политики входа, доверенных прокси, продления и
отзыва сессий. Компиляция Go/Android, Android Lint и тесты на устройстве здесь
**не запускались**: Go и Android SDK отсутствуют. Архив содержит исходники, а не APK.
