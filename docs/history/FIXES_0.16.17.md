# Umbra 0.16.17 — результат изменений

Дата: 13 сентября 2026. Android versionCode: 40. Исходная версия: 0.16.16 (39).

Выбрана облачная модель: ключами управляет сервер, доступ к истории сохраняется
после обычного входа на устройство. Реализовано шифрование содержимого сообщений
и вложений при серверном хранении, а не сквозное шифрование и не копия MTProto.
Android API, конверты сообщений, темы и интерфейс совместимы с предыдущей версией.

## Реализовано

1. `internal/cloudcrypto`: AES-256-GCM для записей, потоковый DARE v2 для файлов,
   отдельный случайный ключ каждого файла, привязка шифротекста к ID и адресации.
2. `internal/store`: шифрование сообщений и квитанций повторов, расшифровка истории,
   запрет запуска с потерянными/подменёнными ключами, маркеры формата хранения.
3. `internal/httpapi`: шифрование загрузок, расшифровка скачиваний с прежним
   контролем доступа, исходными размерами и MIME. Последний байт передаётся после
   проверки завершения потока; неоднозначный ответ БД не удаляет сохранённый blob.
4. `internal/cloudstorage`: перенос сообщений пакетами и вложений через отдельную
   копию с полной проверкой хэша/размера. Повторный запуск продолжает работу;
   публичные ID файлов, квоты и права доступа не меняются.
5. `cmd/storage`: создание ключей без перезаписи, ротация с сохранением истории,
   статус миграции и потоковое шифрование/расшифровка резервных копий.
6. Миграция `015`, физические указатели файлов, корректный GC и очередь удаления.
   Файловое хранилище синхронизирует каталог после публикации/удаления объекта.
7. Обновлены Docker/Compose, systemd, сборка служебного бинарника и инструкции.
   Ключей или пользовательских данных в исходном архиве нет.

PGlite — PostgreSQL в WASM, а не отдельный процесс PostgreSQL 16. Он не заменяет
проверку конкурентной работы и эксплуатации на настоящем сервере БД. Новые
интеграционные тесты включены в существующий CI с PostgreSQL 16 через
`TEST_DATABASE_URL`. Реальный S3/MinIO, Docker, Android-сборка/Lint и device QA
здесь не выполнялись. В Android изменены только номера версии.

## Включение и ограничения

На рабочем сервере сначала нужна согласованная резервная копия БД/файлов, затем
миграция `015`, постоянные ключи с отдельной копией, `umbra-storage migrate` и
проверка нулевого остатка старых данных. Полные команды — `CLOUD_STORAGE.md`.
Архив содержит исходники; установка APK сама по себе не включает серверное шифрование.

Ключи доступны процессу сервера и администратору хоста. Метаданные в базе, история
Room и кэш телефона не шифруются этим изменением. Сохраняется требование HTTPS/WSS.
Прежние резервные копии, WAL, снимки диска и версии объектов требуют отдельной
политики хранения. Ротация сохраняет старые ключи и не перешифровывает уже
зашифрованные записи. Независимый криптографический аудит не проводился.
