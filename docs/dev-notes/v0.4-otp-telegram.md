# v0.4 — вход по номеру с кодом из Telegram (модель «как в Telegram»)

Решение пользователя: приложение для семьи; подтверждение номера кодом, который
приходит в Telegram (бот); один аккаунт на номер; вход с любого телефона по
номеру + коду; вся переписка/профиль подтягиваются из облака. Старые E2EE-
аккаунты удаляются (переход на новую модель).

Это разворот от прежней модели «E2EE, ключи только на устройстве» (Signal) к
облачной модели T1 (как обычные чаты Telegram): сообщения хранятся на сервере и
доступны любому устройству после входа по коду. Приватность — «доверяй серверу»
(TLS + сервер).

## Пользовательские сценарии

Регистрация (один раз на номер):
1. Вводишь номер телефона (E.164).
2. Нажимаешь «Получить код» — код (6 цифр, ~5 минут) приходит в Telegram-бота.
3. Вводишь код → сервер создаёт аккаунт, привязанный к номеру.
4. Вводишь имя (отображаемое) — логин/username генерируется автоматически,
   его можно поменять позже.
5. Готово: чаты пустые (новый аккаунт), можно общаться.

Вход (с любого телефона, в т.ч. нового):
1. Вводишь номер.
2. Если номер есть в базе — приходит код в Telegram, вводишь.
3. Сервер отдаёт профиль и историю; клиент подтягивает переписку, файлы и
   контакты автоматически (история хранится на сервере).

## Как это соотносится с текущим кодом

Сервер уже хранит всю историю сообщений и медиа и умеет отдавать её клиенту
(`GET /v1/messages?since=`, `GET /v1/media/{id}`), номер уже уникален. Изменения:

### Сервер
- **OTP-авторизация** (новая, основной путь):
  - `POST /v1/auth/request_code` `{phone}` → генерирует 6-значный код (TTL 5 мин,
    лимиты на номер и IP), доставляет через Telegram-бота на связанный чат.
  - `POST /v1/auth/verify_code` `{phone, code}` → если аккаунт есть — создаёт
    сессионный токен (вход); если нет — создаёт аккаунт (регистрация, шаг 1),
    возвращает признак `new_account`.
  - Регистрация завершается `POST /v1/register/profile` `{name}` (и опц. username).
- **Привязка телефона к Telegram**: человек один раз пишет боту свой номер
  (`/start`/номер) — сервер запоминает `phone ↔ telegram chat_id`. Код уходит
  в этот чат. Без привязки request_code отвечает понятной ошибкой.
- **Доставка кода**: интерфейс `CodeSender` с реализацией через Telegram Bot API
  (long polling getUpdates, токен в конфиге). Подключается отдельным ботом
  (не конфликтовать с существующим n8n-ботом).
- **Послабление схемы**: колонки ключей `users` становятся nullable — облачным
  аккаунтам Signal-ключи не нужны (старые поля сохраняются для совместимости).
- Миграция `009_phone_otp.sql`: таблица одноразовых кодов, таблица привязки
  phone↔telegram, послабление NOT NULL.
- **Очистка**: старые пользователи и их данные удаляются (переход на новую модель).
- Прежние transfer-эндпоинты (код-перенос) больше не нужны — убираются позже.

### Android
- Экран авторизации переделывается: шаг «номер → код из Telegram → имя».
  Вход: «номер → код → загрузка».
- Обмен сообщениями переводится в облачный режим T1: вместо Signal-E2EE конвертов
  клиент хранит и шлёт сообщения, читаемые после входа по коду (как Telegram).
  Локальные сессии/ключи больше не являются препятствием для нового устройства.
- Контакты: как в v0.3 (телефонная книга + поиск по номеру/имени в семье).
- Медиа: файлы хранятся на сервере, скачиваются после входа.

## Открытые вопросы к пользователю
1. Создать отдельного бота через @BotFather и дать токен (рекомендуется) —
   либо разрешить переиспользовать токен текущего бота из n8n (возможен конфликт
   long-polling).
2. Подтверждение удаления всех текущих аккаунтов и данных на сервере.
3. Нужен ли публичный уникальный логин (username) при регистрации или достаточно
   имени (номер служит идентификатором).
